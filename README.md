# قراصنة البحر — أونلاين

لعبة قراصنة ثلاثية الأبعاد تشتغل في المتصفح (جوال وكمبيوتر)، وكل لاعب عنده جزيرته الخاصة.

## وش فيها
- **جزيرتك**: قلعة وبيوت ومزارع ومنشرة ومنجم ومخزن وحانة وثكنة وحوض سفن وجرس إنذار ومنارة وخزنة. كل مبنى يزيد السكان أو الإنتاج.
- **الدفاعات**: مدافع بحرية ومدافع سلاسل ومنجنيق ناري ومورتر وأبراج رماة ومدفع رشاش ودخان الطوطم وزيت مغلي وسلسلة الميناء وألغام بحرية، وفخاخ مخفية (حفرة، شبكة، برميل بارود، أشواك) وخندق تماسيح، وسور ببوابتين.
- **الحرّاس**: حرس القلعة، طاقم المدافع، رماة الأسوار، الكلاب الحارسة، رجال الإطفاء، الغطّاسين الحرّاس، الفرسان — والمقاتلون من السكان عند دق الجرس، وحرّاس الكنز عند الخزنة.
- **25 نوع قرصان**: بحّار، مبارز، قرصان ببندقية، فني تصليح، مراقب، بسيفين، مدافع، طبيب، طباخ، نهّاب، مدرّع، رامي سكاكين، عازف طبل، الخطّاف، رامي البارود، الملّاح، حامل الراية، هيكل عظمي، الحارق، صياد الحيتان، الجاسوس، قاتل الظل، الغطّاس المخرّب، مروّض الحيوانات، ساحر الفودو، العملاق.
- **الأسطول**: سلوب، بريغانتين، فرقاطة، غليون — مع تطوير الهيكل والمدافع والأشرعة والطاقم، ولون الشراع وتمثال المقدمة، والسفن الثانية ترافقك كمرافقين.
- **العلم**: ارسم علمك بنفسك (24×16)، ويطلع على سفنك وقلعتك. عضو الكلان يطلع علم قائده في زاوية علمه.
- **الكلانات**: اسم الكلان يطلع فوق اسمك كهاشتاق، شات، رتب، خزنة تزيد الإنتاج، وتعزيزات لجزر الأعضاء، وزيارة جزرهم.
- **التحالفات والغدر**: الغدر بحليف يخليك «غدّار» 24 ساعة وعلى راسك مكافأة.
- **الغزو**: اغزُ جزيرة قبطان ثاني، انزل بطاقمك، دمّر دفاعاته وارفع علمك فوق قلعته. درع حماية بعد الغزو، وسجل وانتقام.
- **وحوش البحر**: سفينة الأشباح، الأخطبوط العملاق، وقافلة الملك — يتشارك فيها الكل والغنيمة على قد الضرر.
- **المواسم**: ترتيب بالشرف كل أسبوع وجوائز لأول ثلاثة.

## التشغيل
```
npm start            # السيرفر على المنفذ PORT (الافتراضي 8080)
python3 client/build.py   # يبني server/public/index.html من client/
npm test             # اختبار البروتوكول (يحتاج سيرفر شغّال على 8091)
npm run test:storage # اختبارات حفظ واسترجاع وإعادة تشغيل ببيانات مؤقتة
```
## حفظ بيانات اللاعبين وإعداد Railway

- اربط **Volume موجودًا** بخدمة اللعبة في بيئة production، واجعل Mount Path هو `/data`، واضبط `DATA_DIR=/data` و`NODE_ENV=production` وStart Command إلى `npm start`. شغّل نسخة واحدة فقط؛ هذا التخزين لا يدعم عدة خوادم تكتب في العالم نفسه.
- Railway يضيف `RAILWAY_VOLUME_MOUNT_PATH` تلقائيًا عند ربط Volume. لا تضف هذا المتغير يدويًا لمحاكاة وجود وحدة تخزين. الخادم يشترط تطابقه مع `DATA_DIR`، ووجود المسار وصلاحية قراءته وكتابته، ولا ينتقل إلى مسار آخر عند الفشل.
- تحقق إعداد Railway بالقراءة فقط في 8 أكتوبر 2026: مشروع `pirates-online`، بيئة `production`، خدمة `game`، وحدة `world-data` مرتبطة على `/data`، نسخة واحدة، ولا تغييرات معلّقة. هذا فحص للتهيئة ولا يثبت سلامة محتوى ملفات اللاعبين. لم تُقرأ ملفات اللاعبين أو تُعدّل ولم يُنفّذ نشر أو إعادة تشغيل للخدمة الحقيقية.
- في الإنتاج، غياب ملفات العالم يتسبب في رفض التشغيل أيضًا. إنشاء عالم أول مرة يحتاج `ALLOW_NEW_WORLD=1` **فقط بعد التأكد أن هذه وحدة تخزين جديدة وفارغة**، ثم احذف المتغير. لا تستخدمه كعلاج لاختفاء عالم موجود. وجود ملفات تالفة أو ملفات مؤقتة أو ملفات حجر يمنع إنشاء عالم حتى مع هذا الخيار.
- التطوير المحلي يستخدم `server/data` افتراضيًا؛ يمكن اختيار مسار مطلق بـ`DATA_DIR`. احفظ البيانات التجريبية بعيدًا عن بيانات الإنتاج.

### طريقة الحفظ والاسترجاع

الملف الأساسي `world.json` والنسخة السابقة `world.json.bak`. يتحقق الخادم من البنية قبل قبول ملف الحفظ. إذا تعذر قراءة الأساسي، يحمل نسخة احتياطية سليمة مع تنبيه. تبقى الملفات دون تغيير أثناء التحميل. عند الحفظ التالي يُحتفظ بالأساسي التالف في ملف `world.json.corrupt-*`، ولا يُنسخ فوق النسخة الاحتياطية السليمة. إذا فشل الملفان، يتوقف الخادم قبل استقبال اللاعبين دون إنشاء عالم بديل.

تُكتب الملفات المؤقتة في المجلد نفسه مع `fsync`، ثم تُستبدل بواسطة rename ويُزامن المجلد. تدوير النسخة الاحتياطية يتم بهذه الطريقة أيضًا. فشل الحفظ يُبقي التغييرات معلّمة لإعادة المحاولة ويظهر في السجل؛ `/health` يعيد 503 بعد فشل الحفظ حتى نجاح محاولة تالية. إيقاف SIGTERM/SIGINT يحاول الحفظ ويخرج برمز 1 إذا فشل. الحفظ الدوري كل 8 ثوانٍ؛ الإيقاف القسري قد يفقد التغييرات غير المحفوظة منذ آخر حفظ ناجح.

### قبل نشر الإصلاح

1. تأكد أن وحدة `world-data` الحالية هي نفسها المستخدمة للعالم، ولا تستبدلها بوحدة فارغة. إذا كان العالم في المسار القديم `server/data` بسبب fallback، يلزم إجراء ترحيل منفصل بعد حفظ نسخة منه؛ لا تغيّر المسار أو تنسخ ملفات دون مراجعة.
2. خذ نسخة احتياطية من Volume الحالي قبل أي نشر فعلي، وفعّل نسخ Railway الدورية من تبويب Backups. لا تكفي نسخة `.bak` داخل Volume للحماية من فقدان الوحدة نفسها.
3. شغّل `npm run test:storage`؛ الاختبارات تستخدم مجلدات مؤقتة فقط وتتحقق من الحفظ وإعادة التشغيل وتسجيل الدخول والاسترجاع وأخطاء القرص ومنع إنشاء عالم فوق ملفات موجودة.
4. بعد مراجعة الفرع ونجاح CI، انشر الإصلاح مع الحفاظ على Volume. راقب سطر تحميل العالم و`/health`، دون تسجيل محتويات حسابات اللاعبين.

عند تلف الملفين: احتفظ بهما وبملفات `.tmp` و`.corrupt-*`، وأوقف الكتابة. استرجع نسخة موثوقة بإجراء إداري منفصل؛ لا تحذف الملفات لتمرير فحص الإقلاع ولا تفعّل إنشاء عالم جديد. استرجاع Railway Backup يجهز وحدة مسترجعة ويحتفظ بالوحدة السابقة غير مرتبطة، ويحتاج مراجعة التغيير قبل Deploy.

مراجع Railway: [Volumes](https://docs.railway.com/volumes) و[Backups](https://docs.railway.com/volumes/backups).
